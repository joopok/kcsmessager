# KCS Talk 서버 배포 절차 (2026-11-17 변경분)

운영 서버에 접속할 수 있는 사람이 위에서부터 차례로 진행합니다. 명령은 서버의 프로젝트 폴더에서 실행합니다.
비밀값(토큰 · 비밀번호)과 내부 주소는 이 문서에 적지 않습니다 — 서버의 설정 파일을 직접 확인하세요.

이번 배포로 바뀌는 규칙의 정본은 `claudedocs/KAKAO_FEATURE_SPEC.md` (§2 · §4.1 · §4.2 · §4.5 · §8.2 · §10.10) 입니다.

## 배포 스크립트로 한 번에 (1 · 2 · 4 · 5)

```
bash scripts/deploy_server.sh            # 미리 보기: 받을 커밋 · 배포 전 점검 결과 · 할 일만 보여 준다 (아무것도 바꾸지 않는다)
bash scripts/deploy_server.sh --apply    # 실제 배포: 백업 → 코드 받기(빨리 감기만) → 서버용 패키지 → pm2 다시 시작 → 확인
```

- 겹치는 로그인 아이디 · 커밋하지 않은 수정 · 갈라진 브랜치가 있으면 시작하지 않습니다 (아무것도 바꾸지 않음).
- 실패하면 되돌리는 명령(코드만 · 데이터까지)을 보여 주고, 자동으로 되돌리지는 않습니다.
- 3(nginx)과 5 중 사람이 볼 것(기존 계정 로그인 등) · 6(공지)은 스크립트가 하지 않습니다.

## 1. 데이터 백업

서버가 켜져 있어도 안전합니다 (SQLite 백업 기능으로 한 시점의 내용을 통째로 복사).

```
python3 scripts/backup_db.py                      # server_data/backups/<날짜-시각>/ 에 저장, 최근 14개 보관
python3 scripts/backup_db.py --out /백업/폴더 --keep 30
```

- 저장되는 것: `kakao.db`(대화 · 계정 · 첨부), `rag.db`, `portal_outbox.db`, `org.json`.
- `portal.json`(포털 연동 토큰)은 복사하지 않습니다. 따로 안전한 곳에 보관하세요.
- "백업 완료 → …" 가 나오면 성공입니다. 실패하면 종료 코드 1 과 사유가 나오고 반쯤 만든 폴더는 지워집니다.
- 백업 폴더는 서버와 **다른 디스크나 다른 장비**에도 주기적으로 옮겨 두세요 (같은 디스크만 있으면 디스크 고장에 함께 사라집니다).

### 주기 백업 (cron)

지금까지 주기 백업이 없었습니다. 서버 계정의 crontab(`crontab -e`)에 아래처럼 넣습니다. 경로는 서버에 맞게 바꿉니다.

```
# 매일 03:10 백업, 최근 14일치 보관. 결과는 로그 파일에 남긴다
10 3 * * * cd <프로젝트 폴더> && .venv/bin/python scripts/backup_db.py --keep 14 >> server_data/backup.log 2>&1
```

- 넣은 다음 날 `server_data/backups/` 에 새 폴더가 생겼는지, `backup.log` 에 "백업 완료" 가 찍혔는지 확인합니다.
- 디스크 여유: 백업 한 번의 크기 × 보관 개수만큼 필요합니다 (첨부가 DB 안에 들어 있어 DB 크기와 같습니다).

### 백업으로 되돌리기

1. 서버를 멈춥니다: `pm2 stop kcs-talk-server`
2. 백업 폴더의 파일을 `server_data/` 에 덮어씁니다. `server_data/kakao.db-wal` · `kakao.db-shm` 이 있으면 지웁니다.
3. 서버를 켭니다: `pm2 start kcs-talk-server`

백업 시각 뒤에 오간 대화는 사라집니다.

## 2. 배포 전 점검

```
python3 scripts/predeploy_check.py server_data/kakao.db
python3 scripts/predeploy_check.py server_data/kakao.db --names     # 해당 계정 이름까지
```

DB 를 읽기 전용으로 열고, 아무것도 고치지 않습니다. 결과를 이렇게 봅니다.

| 항목 | 의미 | 할 일 |
|---|---|---|
| 1. 겹치는 로그인 아이디 | 이름 · 사번 · 사내 계정 · 이메일 중 같은 값을 두 계정이 쓰고 있음 | **다시 시작하기 전에** 관리자 화면(구성원 조회 · 수정)에서 한쪽을 고칩니다. 종료 코드 1 이면 이 항목이 있는 것입니다 |
| 2. 실명으로 돌아가는 표시 이름 | 다시 시작하면 프로필 · 멀티프로필의 이름이 조직도 이름으로 바뀜 | 공지에 넣습니다 (아래 6) |
| 3. 비밀번호 미등록 계정 | 등록이 닫히면 혼자서는 시작할 수 없는 계정 | 필요한 사람에게 관리자가 등록 코드를 발급하거나 초기 비밀번호를 정해 줍니다 |
| 4. 관리자 | 그룹 관리자가 1명 이상 있어야 함. 삭제됐는데 관리자 표시가 남은 계정은 정리 | `scripts/set_admin.py --list` · `scripts/set_admin.py <아이디> --off` |
| 6. 파일 전송 보안 새 기본 차단 | 매크로 문서(docm · xlsm · pptm 등) · 7z/rar/alz/egg 를 저장된 정책에 다시 시작할 때 한 번 더함. 관리자가 정책을 저장한 적 없으면 기본 정책이라 바로 적용 | 공지에 넣습니다 (아래 6). 업무에 꼭 필요한 부서가 있으면 다시 시작한 뒤 관리자 화면 [파일 전송 보안…]에서 빼거나 예외를 줍니다 |

## 3. nginx 설정 확인

- TLS 를 종단하는 `stream` 설정에서 `proxy_timeout` 이 **45초보다 길어야** 합니다 (지정하지 않았으면 기본 10분이라 그대로 두면 됩니다). 서버가 조용한 연결에 45초마다 신호를 보내 연결을 유지합니다.
- 서버로 넘길 때 PROXY protocol 을 쓰고, 서버는 `--proxy-protocol` 로 실행하는지 확인합니다 (`ecosystem.config.cjs`). 빠지면 모든 접속이 한 주소로 보여 로그인 실패 제한이 한꺼번에 걸립니다.
- 인증서 만료일과 자동 갱신(갱신 뒤 nginx reload)이 걸려 있는지 함께 확인합니다.

## 4. 코드 받기 → 다시 시작

```
git log --oneline -1                 # 지금 버전을 적어 둔다 (되돌릴 때 쓴다)
git pull
pm2 restart kcs-talk-server
pm2 logs kcs-talk-server --lines 50
```

- 접속 중인 클라이언트는 끊겼다가 자동으로 다시 붙습니다.
- 등록을 예전처럼 열어 두려면 `ecosystem.config.cjs` 의 실행 인자에 `--open-registration` 을 더한 뒤 `pm2 startOrReload ecosystem.config.cjs --update-env` 로 올립니다. 넣지 않으면 **닫힘**입니다.

## 5. 다시 시작한 뒤 확인

- [ ] 로그에 `KCS Messenger 서버 시작` 이 있고 오류로 다시 시작을 반복하지 않는다 (`pm2 status` 의 restart 횟수).
- [ ] 로그의 `표시 이름 N개를 조직도 이름으로 되돌렸습니다` 의 N 이 2번 점검의 숫자와 맞는다 (0 이면 이 줄이 없다).
- [ ] 저장된 파일 정책이 있었다면 로그에 `파일 전송 보안: 새 기본 차단 형태 N개를 저장된 정책에 더했습니다 (…)` 가 있고, 2번 점검 6항목과 맞는다. 한 번 더 다시 시작해도 이 줄이 다시 나오지 않는다.
- [ ] 매크로가 든 문서(예: .docm)나 .7z 파일을 보내면 '보낼 수 없는 파일이에요' 창이 뜬다.
- [ ] 지금 설치된 클라이언트로 기존 계정이 로그인된다 (이메일 + 기존 비밀번호).
- [ ] 로그인 창의 [처음 사용 등록]에서 조직도에 없는 이름으로 등록하면 "등록할 수 없습니다. …" 가 나온다.
- [ ] 관리자 화면에서 미등록 계정에 [비밀번호 재설정…]으로 초기 비밀번호를 정하면 그 계정이 로그인된다.
- [ ] 그룹방에 사람을 초대하면 초대받은 사람에게 초대 안내부터 보인다.
- [ ] AI 비서에게 1:1 로 질문하면 답이 온다 (포털 연동).
- [ ] `python3 scripts/predeploy_check.py server_data/kakao.db` 를 다시 돌려 2번 항목이 0 이 됐는지 본다.

## 되돌리기

코드만 되돌리기 (데이터는 그대로):

```
git checkout <4번에서 적어 둔 버전>
pm2 restart kcs-talk-server
```

- 새 서버가 DB 에 더한 칸 · 색인은 예전 서버가 무시하므로 그대로 두어도 됩니다.
- 다만 새 서버가 **바꾼 데이터**는 코드를 되돌려도 돌아오지 않습니다: 실명으로 되돌린 표시 이름 · 멀티프로필 이름, 삭제한 구성원의 관리자 권한, 새 규칙으로 정리된 첨부. 이것까지 되돌리려면 1번의 "백업으로 되돌리기"를 씁니다 (백업 뒤의 대화는 사라집니다).

## 6. 직원 공지에 넣을 내용

- **처음 쓰는 분**: 관리자에게 등록 코드(30분 동안 한 번)나 초기 비밀번호를 받아 시작합니다. 코드는 로그인 창의 [비밀번호 재설정]에 이름 · 이메일 · 코드 · 새 비밀번호를 넣어 씁니다 (새 버전 앱은 [처음 사용 등록]에 코드 칸이 있습니다).
- **비밀번호**: 새로 정하는 비밀번호는 8자 이상입니다. 지금 쓰는 비밀번호는 그대로 됩니다. 비밀번호를 바꾸면 다른 기기의 접속은 끊기고 다시 로그인합니다.
- **이름 · 이메일**: 표시 이름은 조직도 이름으로 고정됩니다 (바꿔 둔 이름은 실명으로 돌아갑니다). 이메일은 관리자에게 변경을 요청합니다.
- **초대받은 방**: 그룹방에 초대받으면 초대받은 뒤의 대화만 보입니다.
- **링크 미리보기**: 사내 주소(그룹웨어 등) 링크에는 미리보기가 붙지 않습니다.
- **사진 · 파일**: 사진 형식이 아닌 파일을 사진으로 보내면 파일로 도착합니다. 하루에 올릴 수 있는 첨부는 1GB 입니다.
- **보낼 수 없는 파일 추가**: 매크로가 든 오피스 문서(docm · xlsm · pptm 등. 확장자를 docx · xlsx 로 바꿔도 내용으로 알아봅니다)와 7z · rar · alz · egg 압축 파일은 보낼 수 없습니다. 매크로가 없는 형식(docx · xlsx · pptx)으로 저장하거나 zip 으로 압축해 보내세요. 꼭 필요하면 '보낼 수 없는 파일이에요' 창에서 사유를 적어 [승인 요청]을 누르면 관리자가 확인한 뒤 보내 줍니다.
- **로그인 실패**: 같은 자리에서 한 아이디를 5번 틀리면 5분 동안 잠깁니다. 로그인을 저장해 둔 기기는 그동안에도 들어갑니다.
